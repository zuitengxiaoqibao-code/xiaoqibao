# 吏部资金中心设计规格

日期：2026-07-15

## 1. 目标

为默认模拟账户提供独立的吏部资金中心，集中展示可用现金、总权益、持仓占用、现金比例、单票预算上限和总仓位预算上限。用户可以修改预算上限，但每次变更必须追加保存并可验证，历史记录不得更新或删除。

本切片只管理模拟资金和组合预算，不提交委托、不展示完整交易账本、不连接真实券商。户部、兵部和尚书省继续保持独立职责。

## 2. 方案选择

采用“当前设置表 + 追加式额度事件链”的双层方案：

- `paper_settings` 保留当前单票上限和总仓位上限，供风控和模拟成交高频读取。
- `paper_allocation_events` 记录开户初始额度和每次额度变更。
- 每次修改在同一个 SQLite 事务中更新当前设置并追加事件；任一写入失败时全部回滚。
- 事件包含前序哈希和自身 SHA-256 哈希，并由 SQLite 触发器禁止更新和删除。
- 读取资金中心时验证完整事件链；断链、哈希不一致或当前设置与链尾不一致时返回 `503`，不得继续显示为可信状态。

该方案复用现有 `PaperRepository` 事务和锁，不引入第二套账户存储，也不把资金职责迁入户部交易页面。

## 3. 数据模型

### 3.1 资金摘要

`FundsOverview` 包含：

- `account_id`
- `initial_cash`
- `cash`
- `total_equity`
- `position_market_value`
- `cash_ratio`
- `exposure`
- `available_exposure_budget`
- `single_position_cap`
- `total_exposure_cap`
- `largest_position_symbol`
- `largest_position_ratio`
- `positions_count`
- `allocation_event_head`
- `calculated_at`

所有金额和比例使用 `Decimal`。`position_market_value = total_equity - cash`；`available_exposure_budget = max(0, total_equity * total_exposure_cap - position_market_value)`。没有持仓时，最大持仓代码为 `null`、比例为 `0`。

### 3.2 额度事件

`AllocationEvent` 包含：

- `event_id`
- `account_id`
- `previous_single_position_cap`
- `previous_total_exposure_cap`
- `single_position_cap`
- `total_exposure_cap`
- `actor`
- `reason`
- `created_at`
- `previous_hash`
- `event_hash`

开户事件的旧值和 `previous_hash` 为 `null`。后续事件必须引用同一账户上一事件的 `event_hash`。哈希输入采用字段顺序固定、ASCII JSON、无多余空格的规范形式。

升级现有数据库时，为每个已有 `paper_settings` 账户生成一条 `migration_baseline` 事件，额度取当前设置、旧值和前序哈希为 `null`，原因固定为“现有账户额度迁移基线”。该事件只证明迁移时的当前值，不声称还原上线前的修改历史。迁移在仓储初始化事务中幂等执行，重复启动不得生成重复事件。

## 4. 额度规则

额度必须满足：

```text
0 < single_position_cap <= total_exposure_cap <= 1
```

默认值保持单票 `0.20`、总仓位 `0.80`。界面输入以百分比展示，但 API 使用 `0` 到 `1` 的十进制字符串。

额度修改不会追溯拒绝已有持仓，也不会自动卖出。若当前单票或总仓位已经超过新上限，资金中心显示“当前持仓超限”，后续新增暴露由既有刑部规则拒绝；减仓仍允许进入后续规则检查。

`actor` 第一版固定为 `local_user`。`reason` 必填，去除首尾空格后长度为 2 到 200 个字符，作为本地操作留痕，不接受空原因。

## 5. API

新增独立吏部路由：

- `GET /api/v1/funds/accounts/{account_id}`：返回资金摘要和最近 20 条额度事件。
- `PUT /api/v1/funds/accounts/{account_id}/allocation`：更新额度并返回新摘要。

更新请求包含 `single_position_cap`、`total_exposure_cap` 和 `reason`。不存在账户返回 `404`；额度关系非法返回 `422`；事件链或存储损坏返回 `503`；事务冲突或无法持久化时返回 `503`。接口不提供删除、覆盖或回滚历史事件的能力。

## 6. 前端工作区

新增深链 `/funds`，侧栏“吏部 · 资金中心”进入独立页面。页面不嵌套户部订单或兵部委托控件。

桌面布局包含：

1. 资金态势带：现金、权益、持仓占用、剩余额度。
2. 仓位结构：现金与持仓比例、最大单票占比、持仓数量、是否超限。
3. 预算控制：单票上限和总仓位上限的数值输入、修改原因和保存操作。
4. 额度审计流：按时间倒序显示旧值、新值、原因、时间和事件哈希短标识。

移动端使用单列，不使用横向表格。加载、无账户、读取失败、保存中、校验失败、链验证失败和保存成功分别显示。没有账户时只解释需先建立模拟账户，不在吏部页面自动开户。

## 7. 新手解释与风险表达

- “可用现金”说明当前模拟账户尚未占用的现金。
- “总仓位”说明持仓市值占总权益的比例。
- “单票上限”说明任一股票允许占用的最大权益比例。
- “总仓位上限”说明所有股票合计允许占用的最大权益比例。
- 超限状态使用警示色并明确说明“不会自动卖出，但会限制新增暴露”。
- 页面固定显示“仅模拟资金，不连接券商”。

## 8. 错误和并发处理

- 所有仓储读取和写入继续使用 `PaperRepository` 的进程内锁。
- 更新使用 `BEGIN IMMEDIATE` 语义，在一个事务内读取链尾、追加事件并更新当前设置。
- 前端保存期间禁用重复提交；响应返回前切换页面不会产生第二次写入。
- 网络失败后不乐观更新额度，重新读取服务端状态。
- 链验证失败时不展示可能被修改的额度值，只显示明确的完整性错误。

## 9. 测试与验收

后端测试证明：

- 开户生成初始额度事件。
- 额度更新、当前设置和事件链在重启后保持一致。
- 非法额度和空原因被拒绝且不产生事件。
- 模拟中途失败时当前设置和事件均回滚。
- 更新或删除历史事件被 SQLite 拒绝。
- 篡改事件内容、断链或当前设置与链尾不一致会被检测。
- 资金摘要金额和比例使用 Decimal 精确计算。

前端测试与浏览器验收证明：

- `/funds` 深链和前进后退可恢复。
- 保存成功后摘要与审计流同步刷新。
- 非法额度在提交前明确提示。
- 无账户、加载、错误、完整性失败和超限状态不混淆。
- 桌面和移动端无水平溢出，中文标签不截断。

全量验收继续执行后端测试、Ruff、前端测试、生产构建、中文乱码扫描和 `git diff --check`。

## 10. 明确不包含

- 真实资金、银行卡、券商账户或真实下单。
- 入金、出金和初始资金修改。
- 户部完整委托、成交和现金流水页面。
- 兵部观察价位、分批、止损和止盈方案。
- 尚书省指令状态流转。
- 多用户认证和远程操作者身份。
