# 新闻有效事件视图设计

## 目标

修复新闻链接规则升级后，同一不可变事件因行业、主题或标的归属变化而触发 ID 冲突的问题，同时保留完整原始证据链。盘前、盘中和盘后研判读取修正后的有效事件，审计、备份、原始新闻接口和质量基数继续读取不可变原始事件。

## 数据边界

- `news_events` 仍为追加式原始事实，已有记录不更新、不删除。
- `news_corrections` 记录对链接器派生字段的完整替代值，包括标的、行业、主题、关联置信度和审核状态。
- 修正增加 `origin`：旧记录和人工接口默认为 `human`，规则重算生成 `system`。
- 系统修正 ID 由目标派生字段内容生成；重复同步相同目标状态不再追加记录。
- 标题、事件类型、发生时间、归一化时间和引用发生变化时仍抛出完整性错误，不能借修正掩盖原始证据冲突。

## 读取语义

- `events()` 和 `events_for_symbol()` 保持原始审计语义，兼容备份、质量和公开原始事件接口。
- `effective_events(cutoff)` 按追加顺序把不晚于截止时间的修正应用到每个原始事件；未传截止时间时读取最新状态。
- `effective_events_for_symbol()` 在按截止时间应用修正后，再按 A 股代码、`verified` 状态和事件时间筛选，既避免旧归属被重复计入，也避免历史研判使用后来才产生的修正。
- 诊断、数据准备、盘前决策、运行时快照和每日简报只读取有效事件。

## 质量与兼容

- `correction_count` 统计所有追加式修正，反映总修正记录量。
- `human_correction_rate` 只统计 `origin=human` 的不同事件，不把规则升级算成人工干预。
- 旧 SQLite JSON 没有 `origin` 和关联置信度时仍可读取：来源按人工处理，置信度不覆盖原事件。
- 不删除现有运行时数据库，不回填或改写历史事件。

## 验证

用失败优先测试覆盖规则变更同步、原始事件不变、系统修正幂等、有效视图、按标的和截止时间筛选、决策消费者及人工修正率。随后对真实 `600519` 运行准备接口，确认新闻源可用、20 条已验证事件仍可研判，行动和置信度不因本修复改变。
